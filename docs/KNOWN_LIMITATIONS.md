# v0.1 能力边界

这是能运行和继续迭代的初版，不是完整39页方案已经全部实现。以下限制是交付范围的一部分。

## 已有实现但尚待真实账号验收

- Gmail/Graph OAuth、令牌刷新、邮箱身份读取、邮件查询、详情、附件、写操作和发送
- QQ/163 固定 TLS IMAP/SMTP 连接、UIDVALIDITY 校验及基础动作
- Google/Microsoft/QQ/网易自身的授权政策、风控、目录能力和投递结果，不能由本地模拟测试替代
- E3 企业邮件进入个人服务器，必须先确认组织授权和地域/保留政策

## 本轮同步范围

- 当前为有限窗口的轮询/手动刷新，实现并未达到完整方案的 Gmail history、Graph delta、IMAP QRESYNC 增量同步
- 主要提供收件箱、已发送、废纸篓、归档和星标等系统视图，未完整呈现全部 Gmail 标签及自定义目录
- 近期窗口、单次条数和轮询行为以服务端说明为准；客户端显示 PARTIAL，不宣称已加载完整历史
- 外部客户端移动、删除以及窗口外状态校准仍有边界，不把本地缓存当作权威归档
- 搜索仅覆盖已同步的本地元数据，不是提供商全邮箱全文搜索
- 不支持迁移邮箱、永久删除、共享邮箱、企业在线归档或跨账号移动

## 发信与正文

- Web 阅读器支持安全子集 HTML（表格与行内样式），默认阻止远程图片；样式表、媒体查询、CID 内嵌图片暂不渲染，非 Web 平台使用纯文本。详见 HTML_MAIL_READING.md
- 回复/转发提供编辑入口；In-Reply-To/References 线程头未实现，提供商可能显示为新会话
- SMTP 提交成功仅为 ACCEPTED；自动保存已发送副本与核对结果需要后续完善
- 无投递/已读保证；UNKNOWN 禁止自动重发，需要用户到原邮箱核实
- 不同服务商的附件识别可能要在打开详情后才完整；初版限制总原始附件10MiB，并受上游实际总邮件限制
- 无附件预览、杀毒保证、PGP/S/MIME、日历或联系人同步

## 客户端平台

- 已提供六个平台工程；本轮实际编译验证的是 Flutter Web
- Windows/macOS/Linux/Android/iOS 原生包未完成平台构建、签名、安装与真机验收
- 原生平台的安全存储、托盘、系统通知、自动更新、后台限制仍需分别实现或验证
- 没有持久离线缓存与离线变更重放；不要离线后继续编辑并假设已保存
- Web 令牌放内存，刷新后需要重新登录；未实现 TOTP/Passkey、会话刷新及完整设备管理

## 部署与安全

- 设计和当前任务执行器为单节点单用户；不要同时运行多个应用实例
- 当前邮件读模型和草稿以数据库 JSON/TEXT 等简化结构实现，并非完整方案中所有规范化表已落地
- 附件先保存在数据库中；独立文件/对象存储、配额GC和完整生命周期尚未完成
- 当前认证、凭据加密与安全边界测试不等于第三方安全审计
- Docker/Compose 配置已提供，是否执行过容器构建以测试报告为准
- 上线真实邮箱前应添加 HTTPS、验证备份恢复、确认所有真实接入测试、审阅本文件
